# kafka.l3.ManualAckListener — L3

## Идея

При manual ack listener сам определяет момент фиксации offset. Сначала выполняется
бизнес-операция и только затем вызывается `acknowledge()`: ошибка до подтверждения
оставляет запись доступной для повторной доставки.

Spring Kafka 4.1 позволяет задать `ackMode` прямо в `@KafkaListener`. Режим
`MANUAL_IMMEDIATE` коммитит offset сразу, если `acknowledge()` вызван в consumer
thread; вызов из другого потока лишь ставит подтверждение в очередь.

## Что легко сделать неправильно

- подтвердить offset до записи результата в БД;
- проглотить исключение processor и всё равно подтвердить запись;
- вызвать `acknowledge()` асинхронно и ожидать немедленного commit;
- считать at-least-once достаточной защитой без идемпотентности processor.
