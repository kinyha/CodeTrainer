# springweb.l3.ExceptionHandlerProblemDetail — L3

## Идея

`ProblemDetail` задаёт машинно-читаемый контракт ошибки. `type` должен быть
стабильным идентификатором вида проблемы, `instance` — конкретным запросом, где
она произошла, а `detail` может содержать сообщение для текущего случая.

Spring выбирает `application/problem+json` для возвращаемого `ProblemDetail` и
разворачивает `properties` в верхний уровень JSON.

## Что легко сделать неправильно

- вернуть произвольную `Map<String, Object>` и получить разные форматы ошибок;
- использовать URL запроса как `type`, смешав тип проблемы и её экземпляр;
- вернуть stack trace или внутреннее имя класса исключения клиенту;
- забыть проверить Content-Type в MVC-тесте.
